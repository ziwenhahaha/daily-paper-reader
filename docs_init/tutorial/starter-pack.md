# 专题研究：90天/365天/研究方向大礼包

专题研究用于集中了解一个研究方向：确认研究范围，在固定预算内检索、去重、排序与评审，保存最终名单，再分批补充阅读内容。论文复用原阅读页、全文问答与阅读标记，不另建阅读器。

本教程说明当前代码，**不代表你的 Fork 已同步或站点已发布此版本**。旧“研究方向入门包”入口仍指向本页。

## 开始之前

- 在自己的 Fork 同步包含此功能的代码，并配置 GitHub 授权、DeepSeek 与检索所需配置。
- 在 GitHub Pages 操作，由 GitHub Actions 执行，不使用本地工作流替代。Embedding、reranker 使用云端，云端失败会报错，不自动下载本地模型。
- 自动发布当前仅支持已存在的**分支型 Pages（legacy）**，发布源为仓库**默认分支、根目录 `/`**。工作流不会自动创建站点或修改 Pages 配置；自定义 Actions 部署或 `/docs` 发布源需要另行对齐。

## 选择一个专题和研究范围

设置面板有**日常订阅、会议论文、专题研究**三个标签页。日常订阅底部的“想更深入了解一个研究方向？”也可进入专题研究。

1. 保存研究方向词条及关键词、语义查询，再进入“专题研究”。有未保存修改时先保存。
2. 在专题研究自己的选择区**恰好选择一个已保存词条**。这是独立选择，不改变日常订阅的选择或配置。
3. 从三个单选项中选择一种模式：

   - **90天 arXiv**：聚焦近90天研究。
   - **365天 arXiv**：梳理近365天进展。
   - **研究方向大礼包**：近365天 arXiv 加近24个日历月会议论文，并生成方向导读。

4. 设置 **UTC 截止日期（不含当天）**，点击“预览并开始专题研究”。
5. 查看预览，必要时细化一次需求，确认模型调用费用后启动。

大礼包沿用“会议论文”中勾选的**会议名称集合**，不是手选年份。例如只勾选 `ICML 2026`，仍查询 ICML 在滚动24个月内的可用年份；未勾选时使用全部支持会议，如实记录库存缺失与不可用情况。

例如截止日为 `2026-09-12`，365天 arXiv 范围为 `[2025-09-12, 2026-09-12)`，会议为 `[2024-09-12, 2026-09-12)`。均不包含截止日当天；“近两年”不等于两个勾选年份。

## 范围预览与一次细化

默认超过 **1500篇**时提醒范围可能过大，可按研究问题、方法、场景或数据评测条件细化。**最多询问一次**，也可以“继续整个方向”，不会强制缩小范围或自动无限扩评。

细化保存为本次独立需求快照，不写回日常订阅。生成限定查询会调用现有模型；限定词作为组间 AND 检索约束，文字排除要求用于模型评审，不等于数据库 NOT 硬过滤。

阈值是可配置的软提醒，不是结果数量或评分门槛。配置示例（合法范围1–10000整数）：

```yaml
topic_research:
  preview_threshold: 1500
```

预览区分完整计数、下界、部分完成和未知。**大礼包可能只确认 arXiv 部分，会议规模未确认**，此时显示 `partial` 或对应覆盖说明，不能把已知数量说成全量。请求超时或计数预算耗尽也不表示没有论文。

## 固定预算与最终名单

默认处理顺序：

1. 多路召回、保守版本去重与来源资格核验。
2. 融合候选最多 **1000篇**，经云端重排后最多 **300篇**进入最终相关性评审。
3. 在预算内已评分且满足条件的论文中，按相关性分数降序保留最多 **100篇**；合格论文不足不凑数。
4. 先为**全部最终名单**保存基础阅读页、清单与导出，再分批生成内容。

这是**预算内已评分论文的结果，不是全库最优100篇**，也不是找全整个方向的证明。没进入评审预算不等于低相关，模型评分不是人工金标准。

默认每批补充 **10篇**阅读内容。最终名单上限100与单批内容10不同：首批只完成10篇总结，不代表其余入选论文不存在。模型、重排、总结和导读按实际用量计费；只续内容仍可能有费用。

## 在哪里阅读与导出

发布成功后刷新 Sidebar，在**专题回溯**中进入对应任务。每任务提供**结果总览、导读、导出和论文列表**；默认相关性降序，可切换公布日期降序。专题回溯不显示日历，日报日历不变。

- 全部最终论文先有基础页，区分已生成内容和待补充内容。
- 中文标题、摘要、TLDR、速览及核心论文精读沿用原链路；全文不可用会明确说明，不把摘要当成完整 PDF 全文。
- **复制论文清单 / 下载 Markdown**包含整个任务最终名单的标题与外部论文链接，最多100篇，**不受标签筛选、已读状态、分页或首批内容完成情况影响**。
- JSON 下载提供结构化清单；浏览器拒绝复制时可下载 Markdown。

90天/365天主要提供论文结果与阅读内容。研究方向大礼包额外提供有论文引用依据的导读：

- **研究问题**：解决什么问题，适用范围是什么。
- **方法与子方向**：主要方法、分支及其联系。
- **数据与评测**：论文实际使用的数据、任务和指标。
- **近期进展、局限与待研究问题**：区分论文证据与待确认问题。
- **阅读路线与资源**：建议先后阅读顺序，以及有依据的相关资源。

资料不足会明确标注，不编造数据、结论、资源链接或领域历史。阅读路线不等于时间排序；导读依据本次论文，不代表完整教材或权威综述。

## 继续生成，不重新检索

在结果页点击“**继续生成阅读内容**”，按默认每批10篇补充**已经固定的最终名单**，不重新检索、不重新评分、不扩大名单。

保持相同**需求快照、模式、会议范围和截止日期**重复启动，也会继续同一任务的固定名单。不要为了补总结改变日期。需要改变研究问题或时间范围时，创建新的需求或日期任务，重新确认费用；旧任务不会自动无限扩大评审预算。

GitHub 缓存可能被淘汰，但已发布的 `task-state.json` 与 `guide.json` 快照可恢复固定名单和已有导读，需保留这些任务产物。这不代表所有中间缓存永久存在，也不保证失败前尚未保存的调用永不重做。

任务已派发或 Actions 成功，不等于全部内容和导读完成。请检查状态、已完成/待生成数量与错误提示。失败时核对步骤，修正配置或等待服务恢复，再继续对应任务；未完成更新时会保留并标注已有完整快照。

## 日期与覆盖边界

arXiv 按首次提交日期，不随版本更新置顶。会议按有依据的公布日期，保留日、月、年或未知精度；投稿日期、抓取日期和年份占位不冒充精确公布日。

只有来源、日期窗口、摘要和相关性证据满足条件的版本参与最终精选。录用未经核实、日期边界不确定或只有标题的记录，不冒充合格精选；同一作品有符合条件的 arXiv 版本时保留该版本依据。

检索受查询配置、各路 Top-K、库存、RPC 和云端服务可用性限制。DOI、arXiv ID 与标题作者用于保守去重，不确定匹配保留核对信息。建议抽查入选与未入选样本，尤其 ATSP 等相近术语但约束不同的方向。

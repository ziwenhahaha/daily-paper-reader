# 专题研究新版实施与验收计划

本规范以新版专题研究方案为准，替代此前固定12篇设计；实现与验收都需覆盖下面的完整范围。

## 交付范围

- 日常管理、会议论文、专题研究三个页签；日常底部深入研究引导，90/365和大礼包迁入专题研究。日常、10天、30天不改数量和流程。
- 使用已有词条；预览原始英文关键词命中，1500为软提醒，单次澄清且可继续整个方向，不改日常订阅。会议预览不完整时明确partial，不把arxiv部分计数假作全量。
- 三类任务使用固定UTC窗口与安全需求快照，约束词组OR/组间AND实际进入检索；融合池最多1000、云端重排后评审最多300、最终相关性评分降序最多100篇，过滤不合格版本并去重，不凑数。
- 最终名单先发布基础页和完整导出，再每批补齐10篇阅读内容；继续生成不重新召回、评分或扩大名单。固定名单持久保存，不能仅依赖可能淘汰的Actions缓存。
- 大礼包说明研究问题、方法子方向、数据评测、进展局限、阅读路线和已确认资源，依据不足明确说明。导读只组织阅读，不截断完整名单。
- Sidebar专题回溯下每任务有总览/导读/导出和原生论文列表；默认评分，可切公布日期。复制及Markdown下载包含完整最终名单原标题与已确认外部链接，缺链接明确提示，不受已读/过滤/分页影响。
- 保留用户原有路由、全文、笔记和阅读状态；旧完整成果不被失败或待续跑空页覆盖。

## 验收顺序

1. 单元测试验证预算、资格、排序、快照、缓存、1000行截断/超时、导出安全与旧流程不变。
2. 小规模真实匿名预览和云端重排检查；优先复用ATSP/SR/RL已评审缓存，不再次评审几万篇。
3. 独立运行目录验证三种模式的完整名单、分批内容、复制下载和续跑；不写主仓库运行态docs。
4. 浏览器真实HTTP资源检查三个入口、一次澄清、移动端、Sidebar和完整清单复制下载。
5. 提交代码/模板/测试，明确未推送状态。线上Actions/Pages真实验收须在获准推送后进行，不以本地通过冒充线上完成。公告和News另行确认。
